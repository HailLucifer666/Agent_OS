**Root Cause:** Browser auto-launch on boot (`ensureOnline` → `launchLocal` → `chromium.launchPersistentContext('msedge')`) steals the Windows audio input device, causing `NotReadableError: Could not start audio source` when voice-loop calls `getUserMedia({ audio })`. This is a Windows audio driver exclusivity issue — the playwright-launched Edge process locks the mic at the OS level.

**Fix:** Change `browser-automation` boot step in `src/main.js` line 348-363:
- Replace `browserAgent.ensureOnline({ cdpUrl, userDataDir })` with `browserAgent.connect(cdpUrl)` only
- Skip `launchLocal()` at boot entirely
- Log `browser-automation.standby` instead of `offline` when CDP isn't available
- Browser still launches on-demand when `browser_navigate` or similar tools are called — just not at boot

This is a 10-line change in one file. The voice error disappears because no browser process steals the mic at startup.
