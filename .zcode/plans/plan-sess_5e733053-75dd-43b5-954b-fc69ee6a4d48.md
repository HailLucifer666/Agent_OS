# Four Agentic OS Patterns for MYTHOS

## 1. Risk-Classified Pipeline Paths
**File:** `src/core/effectors/pipeline.js` (capture at line 50), new `src/core/effectors/risk-classifier.js`

Create a synchronous classifier that reads card text at capture time and returns a risk class: `tiny-fix`, `quick-win`, `feature`, `architecture-change`. Each class maps to a gate path:

| Class | Gate path | Token cost |
|-------|-----------|------------|
| tiny-fix | build only (skip review) | ~2k |
| quick-win | build → verify → ship | ~5k |
| feature | research → build → visual verify → review → ship | ~15k (P22 full) |
| architecture-change | research → ADR → build → visual verify → review → ship | ~20k |

Classifier uses keyword heuristics: "typo", "rename", "fix" → tiny-fix; "add", "update" → quick-win; "new page", "build", "create" → feature; "refactor", "architect", "redesign", "migrate" → architecture-change.

Inject `classifier` into `createPipelineEffector({fs, classifier})`. Add `card.risk = classifier.classify(card.text)` before writeJSON. The `executePipelineCard` run closure reads `card.risk` and skips/shortcuts the P22 gate accordingly.

## 2. Evidence Validator + Ship Gate
**File:** new `src/core/effectors/evidence-validator.js`, edit `agent-actions.js` (before `moveCard('shipped')` at line 391)

External validator that checks the shipped card has evidence for every required phase. Cannot be bypassed — it runs in the ship closure before `moveCard`.

```js
function createEvidenceValidator() {
  function verify({ card, artifact, review, job, requiredPhases }) {
    var missing = [];
    if (requiredPhases.includes('artifact') && !artifact) missing.push('no artifact produced');
    if (requiredPhases.includes('review') && !review) missing.push('no review recorded');
    if (requiredPhases.includes('review') && review.verdict === 'reject' && !job._reviewRetried) missing.push('review rejected without retry');
    if (requiredPhases.includes('visual') && review && !review.visualDescription && review.checked === undefined) missing.push('visual verification not attempted');
    return { pass: missing.length === 0, missing: missing };
  }
  return { verify };
}
```

Inject into `createAgentActions`. Before `pipeline.moveCard(id, 'shipped')`, call `evidenceValidator.verify(...)`. If it fails, throw — build-runner catches and marks job `failed`. The ship never happens. The card stays in `execute` stage, honest.

`requiredPhases` comes from the risk classifier — tiny-fix needs only `{artifact}`, feature needs `{artifact, review}`, architecture-change needs `{artifact, review, visual}`.

## 3. Credential Scan with Output Redaction
**File:** new `src/core/effectors/credential-scanner.js`, edit `src/core/leash/index.js` (after line 101, post-tier-resolution)

Pattern-based scanner that checks effector args for secrets before T3/T4 execution:

```js
var PATTERNS = [
  { name: 'aws-key', re: /AKIA[0-9A-Z]{16}/g },
  { name: 'google-oauth', re: /ya29\.[0-9A-Za-z\-_]+/g },
  { name: 'api-key-generic', re: /(?:api[_-]?key|secret|token|password)["'\s:=]+["']([A-Za-z0-9\-_]{20,})["']/gi },
  { name: 'private-key', re: /-----BEGIN (?:RSA |EC )?PRIVATE KEY-----/g },
  { name: 'jwt', re: /eyJ[A-Za-z0-9\-_]+\.eyJ[A-Za-z0-9\-_]+\.[A-Za-z0-9\-_]+/g },
  { name: 'connection-string', re: /mongodb(\+srv)?:\/\/[^:\s]+:[^@\s]+@/gi },
];
```

`scan(args)` recursively scans all string values in args. Returns `{found: bool, matches: [{name, sample}]}` where `sample` is the match **redacted** (first 4 chars + `***`). Never echoes the full secret.

Inject `scanner` into `createLeash(deps)`. In `check()`, after tier is finalized (line 101), if `tier >= 3 && scanner`, scan args. If found → deny via existing `writeAudit`/`failClosedIfUnwritable` with reason `credential-detected`. The cortex never executes the effector.

## 4. Eval Regression Gates
**File:** new `test/eval/memory-impact.eval.js`, `test/eval/routing.eval.js`, `test/fixtures/eval/*.json`

Two eval suites that run as tests (via `node --test`):

**Memory-impact eval:** Golden-set fixtures for recall quality.
- Seed episodic store with known records (varying timestamps, salience, kind)
- Assert `recall(query)` returns expected refs in expected order
- After adding a new record, re-run and assert existing rankings didn't regress
- Pin exact scores (the lexical formula is deterministic)

**Routing eval:** Golden-set fixtures for tool selection.
- Seed goals + skills + brain stubs
- Assert `plan(goal, ctx)` picks the correct tool with correct rationale
- Assert `AUTONOMOUS_EXCLUDED` tools are never chosen
- Assert hallucinated tool names are rejected
- Assert arbitration picks the right goal based on priority/drive/urgency

Fixture format: JSON files with `{seed, query, expected}`. The eval loads them, runs the real production code paths, and asserts. When you add a new provider/skill/memory source, run the evals to measure whether MYTHOS got better or worse.
