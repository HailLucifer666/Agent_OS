**RCA: Dual getUserMedia conflict causing NotReadableError**

Two concurrent `getUserMedia` calls hit the same mic with different constraints:
1. `mic-indicator.js:120` `startLevelMeter()` → `getUserMedia({ audio: true })` (bare)
2. `voice-loop.js:338` `ensureMic()` → `getUserMedia({ audio: { echoCancellation, noiseSuppression, autoGainControl } })` (DSP)

On Windows Realtek drivers, re-initializing the device with different DSP settings fails with `NotReadableError`. The mic-indicator's getUserMedia is pure waste — `app.js:63` already routes voice-loop's VAD level via `onActivity → setActivity()`, making the indicator's own analyser fallback unreachable.

**Fix (one line):** In `mic-indicator.js:159`, skip `startLevelMeter()` when the activity callback is already wired (`vadLevel >= 0`):

```js
// Before:
if (state === 'listening') startLevelMeter();
else stopLevelMeter();

// After:
if (state === 'listening' && vadLevel < 0) startLevelMeter();
else if (state !== 'listening') stopLevelMeter();
```

This eliminates the redundant getUserMedia call entirely. Only one stream opens (voice-loop's), no conflict possible. The visualizer still works — voice-loop's VAD drives it through `setActivity()`.

Also kill any lingering Edge process from the previous browser-agent launch (it may still hold the mic).

**Scope:** Single file, 1-line change. No test changes (UI code, no unit tests).
