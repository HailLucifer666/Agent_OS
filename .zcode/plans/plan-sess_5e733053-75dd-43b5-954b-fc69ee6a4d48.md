# Four Fixes: Goals Panel, Panel Close, Web Search Grounding, System Date

## Issue 1: "Show my current goals" doesn't open the panel
**Root cause:** `voice-loop.js:32` — the goals NAV_COMMANDS regex is too narrow:
```js
[/^(show|open)\s+(my\s+)?goals?$/i, 'goals']
```
This matches "show my goals" and "show goals" but NOT "show my current goals" or "show current goals" — the word "current" breaks the pattern. When the regex fails, the command falls through to the brain, which may or may not emit a `navigate` message.

**Fix:** Broaden all NAV_COMMANDS to allow filler words (`current`, `the`, `my`, `active`, etc.) between the verb and the target:
```js
[/^(show|open)\s+(?:my\s+|the\s+|current\s+|active\s+)*goals?$/i, 'goals'],
```
Apply the same broadened pattern to all 7 commands. Also add `(panel|tab|view)` as optional trailing words.

## Issue 2: Dashboard tabs can't be closed
**Root cause:** Investigation shows close IS implemented (× button, backdrop click, Escape key — all in `overlay-manager.js`). But the user says it doesn't work. The likely cause: when a voice command opens a panel via `navigate` WS message, the panel may be opening in a state where the close button isn't reachable, OR the issue is that the user wants a **voice command** to close panels (there's no "close panel" voice command or cortex action).

**Fix:** Add a `close_panel` / `close_panels` voice command to NAV_COMMANDS (or a separate CLOSE_COMMANDS array) that calls `overlays.closeTop()` or `overlays.closeAll()`. Also add a `close` effector tool (`close_panel`) so the brain/cortex can close panels. And verify the × button is actually visible/clickable by checking z-index stacking.

## Issue 3: web_search not being called — agent hallucinates from training data
**Root cause:** The voice agent's RULES prompt (`voice-agent.js:62-79`) **never tells the brain to use web_search for real-time questions**. The tool IS in the catalog, the tier IS 0, the wiring IS correct — but the prompt gives the model no instruction to reach for it. Smaller models (llama-3.3-70b) default to answering from training data unless explicitly told to search.

Worse: the logs show that when the model DID call web_search, it set `needs_result: false` — so the search results were **never fed back into the model**. The model searched, got results, ignored them, and hallucinated anyway.

**Fix (3 parts):**

**3a. Add WEB GROUNDING RULE to the prompt** (voice-agent.js, after INFORMATIONAL TOOLS RULE):
```
WEB GROUNDING RULE (critical for accuracy): For ANY question about current events,
news, dates, weather, real-time data, recent developments, or anything that could
be stale in your training data, you MUST call web_search FIRST and set needs_result:true
to read the results before answering. NEVER answer time-sensitive questions from memory.
If the user asks "what's the latest X" or "check the internet" or "what's happening with Y",
that is ALWAYS a web_search call with needs_result:true. Answering from training data when
you have a search tool is fabrication.
```

**3b. Auto-set `needs_result: true` for web_search/web_fetch actions** (voice-agent.js handleUtterance loop): when the model calls web_search or web_fetch but sets `needs_result: false`, force it to `true` so the results are fed back. The model needs to *read* what it searched for.

**3c. Add cortex web grounding** (goals/index.js plan prompt): same directive for the autonomous cortex — when a goal requires current information, plan() should include web_search in its tool selection.

## Issue 4: Agent stuck on 2024 date — no system date in prompt
**Root cause:** `voice-agent.js buildPrompt()` never injects the current system date/time. The model has no grounding anchor for "today" and defaults to its training cutoff (June 2024). When asked "current date," it hallucinated June 19, 2024 instead of calling `get_time`.

**Fix:** Inject the real system date into every prompt:
```js
// In buildPrompt(), after RULES:
parts.push('', `SYSTEM DATE: ${new Date().toISOString().slice(0, 10)} ${new Date().toLocaleTimeString('en-US', { hour12: false })}`);
```
This gives the model a grounding anchor. Combined with the WEB GROUNDING RULE, "what's today's date" will get the right answer from the injected date, and "what happened in AI this month" will trigger web_search.
