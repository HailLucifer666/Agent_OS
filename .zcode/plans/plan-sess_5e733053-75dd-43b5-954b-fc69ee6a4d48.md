# Quality Gate Overhaul — Research + Visual Verification + Enforced Review

## The Problem (11 defects, 5 structural)

The builder pipeline is ungrounded and unverified end-to-end:
- **No grounding**: `brain.think()` has no tool access. Builder hallucinates from training data.
- **web_search blocked**: `web_search`/`web_fetch` missing from `TIER_TABLE` → default tier 3 → every autonomous call blocked. Agent "searched" 3x, got zero results.
- **No visual verification**: reviewer reads raw HTML text only — never renders the page, never looks at it. `browser_screenshot` + `brain.think({lane:'vision'})` exist but are never wired into review.
- **No quality gate**: ships straight from build to `shipped`. Zero review.
- **Verifier is a stub**: checks first 500 chars, saves failures anyway.
- **Reviewer never fires automatically**, loads no persona, verdict gates nothing.

## The Fix (8 changes across 7 files)

### Phase 1: Unblock Grounding

**1. `leash/tiers.js`** — Add `web_search: 0, web_fetch: 0` to TIER_TABLE.
Read-only research tools. Auto-allow, no confirm gate. **Highest-impact single fix.**

### Phase 2: Research Gate (before build)

**2. `effectors/agent-actions.js`** — Add `researchForBuild()` function:
- Calls `web_search` for the topic (5 results)
- Calls `web_fetch` on top 2-3 URLs to get real content
- Returns a condensed "research brief" (max 2000 chars)
- Injected into the builder's prompt BEFORE generation

The builder now has real, current data to work with instead of hallucinating from parametric memory. This is wired as a dependency (passed from main.js), so it calls web_search/web_fetch directly — bypassing tier gating entirely (internal pipeline code, not cortex-dispatched).

### Phase 3: Visual Verification (after build, before ship)

**3. `effectors/agent-actions.js`** — Add `verifyBuildVisually()` function:
- Opens the built HTML file in the automated browser (`browser_navigate` to the file:// path)
- Takes a screenshot (`browser_screenshot`)
- Sends the screenshot through `brain.think({ lane: 'vision' })` with the prompt: "Does this rendered page match this spec? [spec]. Describe what you see. Is the title correct? Does the content match the topic? Are there placeholder texts or generic templates? Respond JSON: {match: bool, description: string, issues: []}"
- Returns the vision verdict

This is the JARVIS check — MYTHOS literally looks at what it built and verifies it matches the spec. If the vision brain sees a "podcast platform" when the spec says "AI news landing page", it rejects.

**Graceful degradation**: if browser automation is offline (CDP not connected, no Edge launched), skip visual verification and rely on text review + verifier only. Log a warning but don't block the build.

### Phase 4: Enforced Review Gate

**4. `effectors/agent-actions.js`** — Rewrite the pipeline build flow:
```
build → save artifact → verifyBuildVisually() → reviewKanbanCard()
                                                    ├─ approve → moveCard('shipped')
                                                    └─ reject → retry once with issues
                                                                  ├─ approve → shipped
                                                                  └─ reject → shipped-with-issues (honest flag)
```

**5. `effectors/agent-actions.js`** — Fix the reviewer:
- Load `reviewer` persona (`persona:` in enqueue call — currently missing)
- Chain `reality-checker` persona as second check (hallucinated names/brands/stats)
- Increase artifact review from 8000 → 16000 chars
- Either reviewer OR reality-checker OR visual verification rejecting → verdict is reject

**6. `design/verify.js`** — Harden structural verification:
- Check first 2000 chars (up from 500)
- Detect placeholder text patterns ("lorem ipsum", "50,000+ users", "your company", "testimonial")
- Title must contain words from spec
- Content must be topically related

**7. `effectors/build-runner.js`** — Block shipment on verification failure:
If verification fails after retry, mark job `failed` with issues in error (currently saves defective artifact anyway).

**8. `orchestrator.js`** — Wire review into mission flow:
`onBuildDone` invokes `verifyBuildVisually` + `reviewKanbanCard` before counting as `done`. Review reject = `failed`.

## Execution Order
1. Tiers fix (#1) — 2-line change, unblocks everything
2. Research gate (#2) — grounding before generation
3. Visual verification (#3) — render + look at the build
4. Review enforcement (#4-8) — barrier between build and ship

## What this does NOT do
- Does NOT rewrite providers for native tool-calling (research happens in pipeline, not LLM)
- Does NOT add frontier models (separate config decision)
- Does NOT touch brain/index.js signature

## Visual verification fallback chain
```
Browser automation online?
  ├─ YES → navigate to artifact, screenshot, vision brain verify ← FULL CHECK
  └─ NO  → text-only review (verifier + reviewer + reality-checker) ← DEGRADED
```

Browser automation being offline means visual verification is skipped — the build still ships if text review passes, but the `mission.update` / job status will note "visual verification skipped (browser offline)". Honest degradation, not silent failure.
